> - [ ] 初賽後依評審意見改進作品，並補上決賽簡報的「初賽後的改進」

>
> 重新下載後執行 `python -m flowaudit.pipeline`（約 2 分鐘）即可重建 `outputs/tw_sim/` 的全查結果與另一份仿真資料；
> 這些執行產生的檔案不放在 GitHub 上（評估結果 `outputs/tw_sim/evaluation.json` 已隨附）。

依態樣設定門檻的監控規則誤報多、稽核抽樣也不易看出帳戶之間的關係；人頭帳戶的特徵卻藏在「帳戶與帳戶之間的關係」與「資金移動的速度」裡。
FlowAudit 對所有交易**全查**：先用 8 條對應法規態樣的紅旗規則檢核，再把交易建成資金流向圖、萃取 57 項特徵交給 AI 評分，
以 TreeSHAP 說明每個帳戶為什麼可疑，並自動產出可疑交易分析報告與稽核工作底稿。

## 重點成果（台灣情境仿真資料，17,773 個帳戶、758,379 筆交易）

**最接近實務的評估：逐月持續稽核模擬。** 每月 1 日只用當時已有的交易、只知道當時已被警示的帳戶，覆核風險最高的 100 個帳戶：

| 6 個月、共覆核 600 個帳戶 | AI 模型 | 傳統規則 | 隨機抽樣 |
|---|---|---|---|
| 找出的人頭帳戶（不重複） | **97 個** | 62 個 | 約 2 個 |
| 比警方通報更早發現 | **71 個，平均早 20 天** | 39 個 | — |
| 期間內從未被通報、由系統找出 | 26 個 | 23 個 | — |
| 潛在攔阻金額（確認當天凍結） | **1,667 萬元** | 634 萬元 | — |

潛在攔阻金額＝覆核確認當天凍結後，原本還會由被害人直接匯入該帳戶的款項（不計人頭帳戶之間的轉帳，不會重複計算），是仿真情境下的上限。調查延遲的影響（AI）：延遲 1 天 1,516 萬元、3 天 910 萬元、7 天 344 萬元。以每件覆核 30 分鐘、時薪 800 元（假設值）粗估，半年人力成本約 24 萬元，潛在攔阻金額約為其 69 倍（延遲 3 天約 38 倍）；此比值未計入系統建置與誤報處理成本，不是投資報酬率。

**公平比較（覆核同樣多的帳戶）：** 覆核前 243 名（＝人頭帳戶總數）時，AI 找到 229 個、名單中的正常帳戶 14 個；規則（依規則分數排序）找到 131 個、正常帳戶 112 個。要找回 80% 的人頭帳戶，AI 需覆核 195 個帳戶，規則需覆核 829 個。若把命中任一規則的 4,233 個帳戶全部列為可疑，其中 4,009 個是正常帳戶。

**AI 的三個困境與系統的解法**（逐月模擬同樣每月覆核 100 個帳戶）：

| 困境 | 解法 | 結果 |
|---|---|---|
| **導入初期警示資料太少**：第 1 個月自家只知道 7 個警示帳戶，AI 只找到 7 個 | **冷啟動**：自家已知警示帳戶不到 50 個時，先用外部參考資料（代表同業或主管機關分享、已完成調查的資料）訓練的模型，之後改用自家模型 | 6 個月找到 **134 個**（AI 97 個）、平均比警方早 **42 天**、潛在攔阻 **3,924 萬元**（AI 1,667 萬元）。參考資料改用人頭帳戶行為差異很大的資料（較保守）：130 個、3,764 萬元 |
| **沒見過的詐騙手法**：訓練時拿掉一整類手法，AI 只找回該類的 39%～57% | **雙名單**：覆核名額保留 10% 給「規則分數高、但不在 AI 名單」的帳戶；新手法出現後**每月重新訓練** | 平常不減損（逐月模擬 99 個，AI 單獨 97 個）。新手法只要累積 10 個警示帳戶，重新訓練後找回率即升到 61%～93%（解除分期 50%→93%） |
| **循環交易很少被通報**：AI 缺少樣本，只找到 29% | **雙名單的規則名額＋規則保底名單**：覆核名單以外、參與資金循環 ≥ 5 次的帳戶再另列專案查核 | 200 個覆核名額中，規則名單的 20 個有 14 個是循環交易帳戶，加上保底名單（36 個）找回 **17/17**；外部資料為 9 個＋9 個，找回 **18/18**。代價是覆核名額內少找到 1～2 個其他人頭帳戶（全給 AI 為 200 個，雙名單為 198～199 個） |

**其他驗證：**

| 評估 | 結果 |
|---|---|
| 多模型比較（集團層級 5 折交叉驗證，PR-AUC，95% 信賴區間） | XGBoost 0.981 [0.968, 0.992]、隨機森林 0.989、邏輯斯迴歸 0.906、**現行規則 0.628**、規則加權（依警示資料學權重）0.616、孤立森林（非監督）0.274、隨機 0.014 |
| AI 的進步從哪裡來 | 只替 8 條規則的「是否命中」學權重：0.616，與現行規則相近；改用 16 項規則背後的連續數值（不切門檻）：**0.966**；全部 57 項特徵：0.981。大部分進步來自「不把規則切成是／否」，資金網路圖等其餘特徵提供較小的額外幫助 |
| 仿真穩健性測試（同一仿真器、另一個隨機種子，模型不重新訓練） | AI 0.959｜規則 0.572 |
| **獨立來源合成資料的重新訓練驗證：IBM AMLworld HI-Small**（IBM 另一套模擬器產生的合成資料，與本專案仿真器無關；以同一套程式在該資料上**用它自己的標籤重新訓練**、5 折交叉驗證，驗證的是方法而非已訓練的模型；[完整結果](docs/外部驗證_AMLworld.md)） | 美元交易 167 萬筆、16.2 萬個帳戶、洗錢帳戶 1.67%：**AI 0.302**（隨機 0.017 的約 18 倍），覆核前 200 名有 199 個是洗錢帳戶（占全部洗錢帳戶 7.4%）；**規則 0.020，約等於隨機**。AI 仍有效，但成效明顯低於台灣情境仿真資料：覆核前 2,707 名（＝洗錢帳戶總數）時找回 31% |
| 警示資料稀少（隨機只保留部分已警示帳戶訓練） | 只知道 25%（54 個）：AI 0.887；只知道 5%（11 個）：AI 0.745（三次抽樣 0.707～0.769），仍高於規則 0.628 |
| 壓力測試（隱蔽型人頭、慢速轉出、分散收款、困難正常樣本加倍、以上全部） | AI 重新訓練 0.944～0.989、不重新訓練 0.959～0.986；規則 0.132～0.596。在仿真器能產生的變化內 AI 都很穩定，規則在「以上全部」情境幾乎失效 |
| 未被通報的人頭帳戶 | 28 個期間內從未被警示，AI 在前 243 名中找出 16 個 |
| 誤判分析 | 覆核同樣 243 個帳戶時，AI 名單中的 14 個正常帳戶主要是學生、代收帳戶與第二帳戶，規則名單中的 112 個主要是個人賣家（49）與上班族（45）。若以命中任一規則為準，100% 的團購主與代收帳戶、99% 的發薪公司、96% 的房東會被列為可疑 |
| 各詐騙類型檢出率（前 243 名） | 假投資 99%、網購詐騙 99%、解除分期 100%、**循環交易 29%**（以規則保底名單補足） |
| 消融實驗 | 任一類特徵拿掉後 PR-AUC 最多只降 0.013，系統不依賴單一訊號。拿掉 14 項資金網路圖特徵只從 0.983 降到 0.981，資金流向圖對排序的額外貢獻很小，主要用於集團調查與循環舉證 |
| 資金流向圖的調查價值 | 系統切出的 24 個疑似集團，每一個都只對應單一真實詐騙集團（涵蓋 20 個中的 17 個，未涵蓋的 3 個是循環交易）；從已警示帳戶沿資金往下游追一層、再篩命中紅旗規則的帳戶，59 個帳戶中有 20 個是警方尚未通報的人頭帳戶（34%，隨機 1.4%），其中 8 個是循環交易 |

> **限制：** 以上皆為**合成資料**。仿真器依公開資料設計並刻意加入大量「像人頭帳戶但正常」的帳戶，仍不等於真實資料。
> 壓力測試與冷啟動的參考資料也出自同一個仿真器，冷啟動在真實跨機構資料上的效果會低於模擬結果。
> 在與本專案無關的公開合成資料（IBM AMLworld，以其標籤重新訓練）上，AI 的 PR-AUC 為 0.302，遠低於本專案仿真資料的 0.98，代表本專案的仿真資料偏容易；真實銀行資料上的成效尚待驗證。
> 實際導入須以機構自有資料重新訓練與驗證。報告書與簡報請主動說明這一點。

## 快速開始

需要 Python 3.10 以上。

| 系統 | 做法 |
|---|---|
| Windows | 雙擊 `run_windows.bat` |
| macOS / Linux | 執行 `./run_mac_linux.sh` |

第一次執行會安裝套件並完成全查與模型訓練（約 2～3 分鐘），接著開啟儀表板 <http://localhost:8501>。
評估結果（`outputs/tw_sim/evaluation.json`）已隨附；要重新評估可在「模型評估」頁按鈕執行，或用下方指令。
不同版本的 XGBoost／scikit-learn 會讓數字有小幅差異；要完全重現 README 的數字，請改用 `pip install -r requirements-lock.txt`。

```bash
pip install -r requirements.txt
python -m flowaudit.simulator         # 重新產生台灣情境仿真資料（已隨附，可略過）
python -m flowaudit.pipeline          # 規則全查 + 特徵 + 模型訓練 + 外部驗證
python -m flowaudit.evaluation        # 多模型比較、消融、逐月模擬、誤判分析、警示稀少、新手法測試、保底名單（約 15 分鐘）
python -m flowaudit.evaluation --stress   # 另外重跑壓力測試（再加約 15 分鐘；未加時沿用上次結果）
streamlit run app.py                  # 開啟儀表板
pytest -q                             # 執行測試
```

## 系統架構

```
交易資料（時間、金額、管道、登入裝置、開戶資料）
   │
   ├─① 規則引擎（rules.py）         8 條紅旗規則全查，每條對應調查局疑似洗錢態樣或金管會管理辦法，附證據文字
   ├─② 特徵工程（features.py）      交易行為、資金流速、時間與管道、資金網路圖、帳戶屬性與裝置，共 57 項
   ├─③ 風險模型（model.py）         XGBoost；只用「已被警示」的帳戶訓練（貼近實務），集團層級交叉驗證
   ├─④ 可解釋性（model.py）         TreeSHAP：逐帳戶拆解每個特徵對風險的貢獻
   ├─⑤ 疑似集團偵測（pipeline.py）   在可疑帳戶子圖上做 Louvain 社群偵測
   ├─⑥ 覆核名單（model.py）         AI 名單＋規則名單（新手法保險，預設 10% 名額）＋規則保底名單（資金循環 ≥ 5 次，另案查核）
   ├─⑦ 報告生成（report.py）        模板／LLM 撰寫可疑交易分析報告，匯出 Word 與 Excel 工作底稿（含三份名單）
   ├─⑧ 嚴謹評估（evaluation.py）    多模型比較、消融、逐月持續稽核模擬（含冷啟動、雙名單）、成本效益、誤判分析、
   │                                警示稀少、新手法測試、規則保底名單、壓力測試
   └─⑨ 稽核儀表板（app.py）         7 個頁面，可上傳新資料現場全查
```

### 紅旗規則（門檻在 `config.yaml` 調整，不需改程式）

| 代碼 | 規則 | 對應態樣／法規 | 判斷方式（預設） |
|---|---|---|---|
| R1 | 快進快出 | 態樣 A15、A16、A17 | 流入後 24 小時內轉出或提領 ≥ 80%，至少 2 次 |
| R2 | 集中匯入 | 態樣 A17 | 7 日內不同匯入來源數 ≥ 該客群第 95 百分位 |
| R3 | 分散匯出 | 態樣 A18 | 7 日內不同匯出對象數 ≥ 該客群第 95 百分位 |
| R4 | 資金循環 | 態樣 A18 | 依時間先後、金額相近（0.5～1.2 倍）經 2～5 個帳戶回流，30 日內完成 |
| R5 | 休眠／新戶突然活躍 | 態樣 A15、A16；管理辦法第 4 條 | 開戶 ≤ 90 天或未往來 ≥ 180 天，開始使用 14 日內流入 ≥ 5 萬且轉出 ≥ 70% |
| R6 | 密集現金提領 | 態樣 A11、A12 | 24 小時內 ATM／臨櫃提領 ≥ 3 次且 ≥ 5 萬元 |
| R7 | 多帳戶共用裝置 | 態樣 A1G | 同一登入裝置有 ≥ 3 個帳戶轉入同一受款帳號 |
| R8 | 小額測試交易 | 管理辦法第 4 條 | 72 小時內 ≥ 3 筆 30 元以下轉出入 |

「態樣」指法務部調查局〈疑似洗錢或資恐交易態樣〉銀行業代碼；「管理辦法」指《存款帳戶及其疑似不法或顯屬異常交易管理辦法》。
規則門檻依客群（個人、商家、公司）分別計算。資料缺少時間、現金、裝置或開戶欄位時，對應規則自動改用替代判斷或不觸發。

## 評估方法為什麼可信

1. **只用已警示帳戶訓練：** 銀行實際只知道「已被通報」的警示帳戶。模型只用這些訓練，但以全部真實人頭帳戶評估，才看得出能否找到「還沒被通報」的帳戶。
2. **集團層級交叉驗證：** 同一詐騙集團的帳戶不會同時出現在訓練與測試，避免模型只是記住某個集團。
3. **逐月持續稽核模擬：** 每月只用當時已有的資料；被找到的帳戶當月凍結，不重複計算。已知警示帳戶不到 5 個時自動退回規則排序；另比較冷啟動（先用參考資料訓練的模型）與雙名單。
4. **大量困難的正常樣本：** 團購主、標會會頭、代收班費、個人賣家、發薪公司、薪轉後轉出、休眠後領保險金、家人共用手機、記帳士代管網銀等。
5. **主動找出 AI 會失效的情況：** 訓練時拿掉一整類詐騙手法（新手法測試）、只保留少數警示帳戶（警示稀少）、改變人頭帳戶行為（壓力測試）。規則保底名單列出所有門檻的結果，並在另一份資料上驗證，不只報告選定的門檻。
6. **誠實呈現負面結果：** 隨機森林的 PR-AUC 略高於 XGBoost（採用 XGBoost 是因為能精確計算 TreeSHAP 且訓練快）；「規則＋AI 加權」的雙層排序反而比 AI 單獨排序差；
   循環交易檢出率只有 29%；沒見過的手法 AI 只找回 39%～57%；AI 的進步大部分來自保留規則的連續數值，資金網路圖特徵的額外貢獻較小；
   冷啟動的參考資料與自家資料出自同一個仿真器，是偏樂觀的估計。在 AMLSim 資料上，規則基準線的次要排序（快進快出金額占比）反而不利：
   覆核前 500 名命中率 38%，只看命中規則數則為 77%（PR-AUC 0.487 對 0.499，差異小）。
   在 IBM AMLworld 上 AI 只有 0.302、規則幾乎失效（規則依台灣人頭帳戶態樣設計，且該資料沒有現金、裝置、開戶日欄位）；
   該資料沒有集團資訊，只能用一般分層交叉驗證，數字可能略為偏樂觀。

## LLM 報告生成（選用）

預設用模板產生報告，**完全離線也能運作**。要改由大型語言模型撰寫，先設定環境變數：

```bash
# Windows (PowerShell)
$env:ANTHROPIC_API_KEY="你的金鑰"      # 或 $env:OPENAI_API_KEY="..."
# macOS / Linux
export ANTHROPIC_API_KEY=你的金鑰
```

模型名稱可在 `config.yaml` 或環境變數 `FLOWAUDIT_ANTHROPIC_MODEL`、`FLOWAUDIT_OPENAI_MODEL` 修改。
送給 LLM 的只有「結構化事實」（規則證據、SHAP 依據、交易統計），並要求不得杜撰；呼叫失敗時自動退回模板。
