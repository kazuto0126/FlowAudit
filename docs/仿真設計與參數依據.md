# 台灣情境仿真資料：設計與參數依據

真實銀行交易資料受個資法與銀行保密規定保護，學生無法取得。本專題依公開的法規、統計與新聞報導，
設計一個「看起來像台灣銀行」的交易仿真器（`flowaudit/simulator.py`），並刻意加入大量
**行為像人頭帳戶、但其實完全正常** 的帳戶，避免模型只學到仿真器的破綻。

> 本資料為合成資料，不含任何真實個人資料。人頭帳戶比例約 1.4%，刻意高於真實情況，以利訓練與評估。

## 一、規模與期間

| 項目 | 數值 |
|---|---|
| 期間 | 2026-01-01 ～ 2026-06-30（6 個月） |
| 帳戶數 | 17,773 個（個人、商家、公司） |
| 交易筆數 | 758,379 筆（含現金存提） |
| 人頭／可疑帳戶 | 243 個（20 個詐騙集團；其中 28 個在期間內未被通報） |
| 被害人匯入金額 | 約 9,420 萬元（760 名被害人） |
| 欄位 | 交易時間（到分鐘）、金額（新台幣）、交易管道、登入裝置、開戶日、觀察期前未往來天數、客戶類型 |

## 二、詐騙金流設計

| 設計 | 依據 |
|---|---|
| 被害人 → 第一層人頭帳戶 → 第二層人頭帳戶 → 車手 ATM 提領或轉入虛擬貨幣交易所 | 報導者指出詐團以第一、二、三層帳戶層層轉帳後由車手提領，並利用虛擬貨幣、第三方支付移轉；聯合報報導屏東地檢署破獲「五層式」分工詐團，款項最後購買虛擬貨幣 |
| 款項在數小時內轉出（部分隔 1～3 天、部分只轉出一部分） | 報導者：詐團利用警方調閱資料需一、兩個月的時間差，在數小時內跨帳戶移轉 |
| 人頭帳戶來源：新開戶、久未往來的休眠帳戶、被出售的正常帳戶 | 報導者：帳戶在社群與地下論壇收購，價格逐年上漲 |
| 收購後先做小額測試交易（約半數） | 《存款帳戶及其疑似不法或顯屬異常交易管理辦法》第 4 條第二類：「存款帳戶內常有多筆小額轉出入交易，近似測試行為者」 |
| 約六成人頭帳戶由集團以少數裝置統一操作 | 調查局疑似洗錢態樣 A1G：「多個客戶網銀交易透過同一電腦 IP 位址辦理，且密集轉入相同受款帳號」 |
| 被害人報案後帳戶警示凍結，集團換下一個人頭帳戶；部分第二層帳戶在觀察期內未被發現 | 《存款帳戶及其疑似不法或顯屬異常交易管理辦法》第 3 條警示帳戶定義；全台警示帳戶 2026 年 1 月約 14.85 萬戶 |
| 詐騙類型：假投資（金額大、較晚發現）、網購詐騙（案件多、金額小）、假客服解除分期（夜間 ATM 轉帳）、循環交易（公司帳戶間空轉） | 165 打詐儀錶板：2025 年詐騙財損約 893 億元、16.2 萬件，網購詐騙案件數最多、假投資次之 |

## 三、金額與限額參數（各銀行不同，僅作仿真參數）

| 參數 | 仿真設定 | 依據 |
|---|---|---|
| ATM 單次提款上限 | 2 萬元 | Money101 整理：多數銀行 ATM 跨行提款單次上限 2 萬元 |
| ATM 每日提款上限 | 15 萬元 | 玉山銀行 FAQ：金融卡每日提款限額最高 15 萬元 |
| 非約定轉帳 | 每筆 5 萬元（假投資被害人多以 1～5 萬元分次匯款） | 常見設定每筆 5 萬、每日 10 萬、每月 20 萬（各銀行不同） |
| 解除分期被害人 ATM 轉帳 | 略低於 3 萬元（如 29,985 元） | 常見 ATM 非約定轉帳每日 3 萬元上限 |
| 大額通貨交易申報門檻 | 50 萬元（供規則與報告參考） | 《金融機構防制洗錢辦法》第 2 條：一定金額為新臺幣 50 萬元 |

## 四、容易被誤判的正常帳戶（hard negatives）

| 類型 | 行為 | 容易觸發的規則 |
|---|---|---|
| 團購主、代收班費 | 短期內大量會員匯款，隨即整筆付給廠商 | 集中匯入、快進快出 |
| 標會會頭 | 每月固定日多名會員繳會款，隔天整筆交給得標者 | 集中匯入、快進快出 |
| 個人賣家（網拍、二手、代購） | 新開或久未使用的帳戶，一段期間內很多買家小額匯款，再 ATM 提領 | 休眠／新戶、密集現金提領、快進快出 |
| 發薪公司 | 同日匯薪給數十名員工 | 分散匯出 |
| 薪轉後立刻轉到自己其他帳戶 | 薪水入帳數小時內轉出 60～100% | 快進快出 |
| 第二帳戶（儲蓄、特定用途、極少使用） | 交易稀疏、使用期間短，常是久未往來帳戶；買車頭期款等一次性大額進出 | 休眠／新戶、快進快出 |
| 休眠後領保險金或遺產 | 一筆大額入帳後轉給家人、臨櫃提領 | 休眠／新戶 |
| 家長用同一支手機管理子女帳戶、記帳士代管多家公司網銀 | 同一裝置多帳戶轉入同一受款人 | 共用裝置 |
| 電子支付綁定驗證 | 1～5 元驗證入帳 | 小額測試 |
| 夜班工作者、虛擬貨幣投資人、期間內結清的帳戶 | 深夜交易、轉入交易所、使用期間短 | — |

## 五、評估設計要點

- **只用已警示帳戶訓練**：銀行實際只知道「已被通報」的警示帳戶；模型用這些訓練，但以全部真實人頭帳戶評估，才能看出能否找到「還沒被通報」的帳戶。
- **集團層級交叉驗證**：同一詐騙集團的帳戶不會同時出現在訓練與測試，避免高估。
- **逐月持續稽核模擬**：每月 1 日只用當時已有的交易與已知警示帳戶，最接近實際導入情境。
- **外部驗證**：用另一個隨機種子產生的仿真資料（不同帳戶、不同集團）測試未見過的資料。
